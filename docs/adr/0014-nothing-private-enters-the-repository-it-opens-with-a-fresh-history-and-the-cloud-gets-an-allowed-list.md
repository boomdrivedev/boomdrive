# Nothing private enters the repository, it opens with a fresh history, and the cloud gets an allowed list of Flume's status

Status: accepted by the user on 2026-11-02, approving on Pending You the card that asked to open the repository publicly from a fresh history; proposed on 2026-11-01 from the user's words in the constitution interview.

Deciders: the user, 2026-11-01.
Sources: the constitution interview of 2026-11-01 (`design/research/the-constitution-interview.md`), its topic on what stays private; record 0012; agentplot/flywheel-next, the spike `research/board-shows-flume-sluice-and-timber` of 2026-11-01, the fields its drawings read; agentplot/flywheel-cloud's rules core.4 and core.48, cited by id; rules core.6 and core.11.

## Context and problem statement

The repository is to be public (record 0012). As it stands, it names the operator's hosts and partitions and the tool that keeps the operator's machines. It cites a private repository's records, rules and ledger with short quotes, and its Flume fixtures hold home paths and Flume's whole status of scratch places.

What goes up was open too. Flume's status of a place is carried whole, as Flume printed it, to crew's state repository and, as built, to any control plane. That status holds the agent's whole prompt with the brief, its screen, dialog and last words, the change's task text, the caller's words and paths. The cloud holds no repository content (cloud core.4), and core.11 allows a field left out that holds content the cloud may not hold.

## Considered options

For going public: a rule now, the tree scrubbed, and a fresh public history; the rule and the scrub, with the history published as it is; or the history rewritten.

For what goes up: an allowed list, the fields the cloud's copy of a place names; a deny list; or the status whole, encrypted by the cloud for each customer.

## Decision outcome

Option 1 each time, the user's choice. For what goes up, the user pointed to the board spike's session for what the cloud would show.

- **No private text or names.** No text of a private repository is copied into this one, which cites a private repository by its name and an id at most. No host, partition, state repository, person's path or account appears in its code, tests, fixtures or docs. Tests use neutral names, and a tool's answer kept as a fixture is captured on a scratch host with its paths made neutral (core.41).
- **A fresh history.** A change scrubs the tree to that rule. The public repository starts from a fresh history, and this one is kept private as its archive.
- **An allowed list for the cloud.** To a hosted control plane, the runner carries of Flume's status of a place only the fields the cloud's copy of a place names, each as Flume printed it, and leaves out the rest. The list is that copy's schema, in the runner protocol (core.27). The spike's drawings read these fields: `place`, `branch`, `base`, `stream`, `priority`, the agent's account, `stages[]` with their ends, `ends[]` with their deliveries and who they are pending for, `waiting_on`, the submission's counts, the pane's address for the terminal, and each stream's running and bound. That is the list's first draft. An agent's question to a person, its waiting and end words, is among what is kept. crew's state repository, the operator's own, takes the status whole as now.

core.6 stands, and its details are amended in this record's commit to name the repository as public. core.11's details are amended to name the allowed list as what goes to a hosted control plane.

### Consequences

- Which of the spike's fields that carry a repository's or a terminal's text go up, field by field, is for the copy's schema to settle in the change that builds the hosted implementation. Among them are a group's title from `tasks.md`, an end's words, and the dialog behind `why: dialog`.
- crew's public README and specs name this repository, its rule ids and the operator's hosts and partitions. That is crew's to scrub, with the same rule as the model.
