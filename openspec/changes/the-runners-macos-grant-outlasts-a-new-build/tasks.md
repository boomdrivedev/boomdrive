# Tasks

Work through the tasks in order. A task is true once the check it names passes, run as it names it. The groups are headings for reading.

- **The checks.** Every activation case runs in a scratch folder of its own, over stubs of `security`, `codesign`, `openssl`, `mv` and `id`. No case reaches a real keychain, signs a real program or touches anything of the gate's host outside its folder, and every name in a case is neutral (core.4, core.41; design Decision 7). Every evaluated case runs against no store, as `nix/check.sh` does.
- **What no task adds or changes.**
  - No task adds a crate, a tool of the gate, a tracked file type, an option, a configuration key, a field of `report.json` or a message of the protocol (core.7, core.8, core.17).
  - The runner's code does not change.
  - Nothing outside the paths `proposal.md`'s Touches lists is changed.
- **What is already written.** This change's own commit holds record 0045, core.59 and core.46's amended details. No task changes them. A task that relies on a choice the design names cites its Decision.
- **What is carried.** Tasks 1.1 and 1.2 take code written on `change/a-new-build-keeps-the-runners-macos-access`, read with `git show db31f8b5 -- nix/` and `git show e3d8962e:nix/modules/activate.sh` and `git show e3d8962e:nix/tests/activate.sh`, merged into the files as `main` now holds them, never cherry-picked (design Decision 8).

## 1. The signing step

- [x] 1.1 `nix/modules/activate.sh` gains `sign <keychain> <folder> <program>`, as `db31f8b5` writes it, in its header comment and its usage lines after `managed`, its header naming record 0045 and design Decisions 1 to 4 of this change. The step makes `<folder>` with `mkdir -m 0755` where nothing is there. It reads the folder's owner and mode from `ls -ldn`. Where the folder is no folder, its owner is not `id -u`, or its mode gives write to the group or to others, it makes no identity, signs nothing and writes nothing in the folder; it says `boomdrive: <folder> is writable by a user other than <user>: signed nothing` and exits 1 (design Decision 3). Throughout the step, a line of what it made goes to standard output and a refusal to standard error, as `link`'s do. `nix/tests/activate.sh` takes `db31f8b5`'s header words, its `id` stub answering `-u` with the case's `uid`, its `run` giving each case a `TMPDIR` of its own, and its `freshSign` with the stubs of `security`, `codesign` and `openssl` of design Decision 7, merged with the managed document's cases `main` holds. It gains the case "A folder another user can write", which runs the step with the folder `chmod g+w`, with it `chmod o+w`, and owned by another uid, each asserting the line, exit 1, no call of `security`, `codesign` or `openssl`, and an empty folder; and the case "sign's usage", where two words or four after `sign` exit 2 and make no folder. True when `sluice exec main -- moon run nix:test` passes.
- [ ] 1.2 The step finds and makes the identity as `e3d8962e` writes it (design Decision 2). It finds the identity by the distinct SHA-1s on the lines naming `"Boomdrive runner"` in `security find-identity -p codesigning <keychain>`, and a listing `security` cannot give makes none and fails. With none, it writes the OpenSSL configuration and runs `openssl req -x509 -newkey rsa:2048 -nodes -days 7300` in a folder made by `mktemp -d "${TMPDIR:-/tmp}/boomdrive.XXXXXXXX"` under `umask 077`, which a trap removes. It runs `security import key.pem -k <keychain> -x -T /usr/bin/codesign`, then `security import cert.pem -k <keychain>`, and says `boomdrive: made the code-signing identity Boomdrive runner, <SHA-1>, in <keychain>`. A refused import removes the folder, says `boomdrive: could not make the code-signing identity in <keychain>: <its words on one line>`, signs nothing and exits 1. Two or more identities sign nothing and say `boomdrive: <keychain> holds <n> identities named Boomdrive runner, <SHA-1>, …: signed nothing; remove all but one`, then exit 1. `nix/tests/activate.sh` takes `e3d8962e`'s cases "No identity yet", "No key in a file", "An identity that cannot be made" and "Two identities of the name", which prove the service-modules delta's scenarios of those names but for the copy's signing, which 1.3 adds. "No key in a file" finds no file reading `key` or `cert` in the case's folder or in the folder `openssl` wrote in. True when `sluice exec main -- moon run nix:test` passes.
- [ ] 1.3 The step makes a copy where `<folder>/boomdrive` is not there, `<folder>/boomdrive.source` does not hold `<program>`, or `codesign --verify -R '=certificate leaf = H"<SHA-1>"' <folder>/boomdrive` fails; otherwise it says nothing and exits 0. It makes one in design Decision 4's order: `cp` to `boomdrive.new` with mode 0755; `codesign --force --sign <SHA-1> --keychain <keychain> --identifier boomdrive --timestamp=none` on it; `rm -f` of `boomdrive.source`; `mv -f` to `boomdrive`; `<program>` written to `boomdrive.source.new` and moved by `mv -f` to `boomdrive.source`; then `boomdrive: signed <folder>/boomdrive, made from <program>, with Boomdrive runner, <SHA-1>`. A failed `cp` or `codesign` removes `boomdrive.new` and leaves `boomdrive` and `boomdrive.source` as they were; a failed `mv` removes what is left of `boomdrive.new` and `boomdrive.source.new`, leaving no `boomdrive.source`; each says `boomdrive: could not sign <program> into <folder>: <its words on one line>` and exits 1. `nix/tests/activate.sh`'s `freshSign` gains the `mv` stub of design Decision 7, which runs the system's own `mv`, found before the stubs, where the case has no `refuse-move`. It gains the cases "A new build", "The same build", "A copy signed with another identity", "A signing refused" and "A copy not put in place", which prove the service-modules delta's scenarios of those names. "A new build" asserts `boomdrive.source` holds the program and the copy holds `signed <SHA-1>`. "The same build" asserts no signing call of `codesign` and both files' bytes unchanged. "A signing refused" asserts the folder holds only `boomdrive` and `boomdrive.source`, as they were. "A copy not put in place" refuses the move onto `boomdrive` and asserts `boomdrive` as it was, no `boomdrive.source` and no other file. "No identity yet" now also asserts the copy holds `signed` with the identity made. True when `sluice exec main -- moon run nix:test` passes.
