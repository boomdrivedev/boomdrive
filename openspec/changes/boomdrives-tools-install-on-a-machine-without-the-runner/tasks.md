# Tasks

A task is done once the check it names passes, run as it names it. The task groups are headings for reading: no task checks a group, and the verify stage runs the repository's whole checks once every task is done.

- **The checks.** Every evaluated case runs against no store, as `nix/check.sh` does, with core.41's neutral names. No case builds a package or reaches the network. A case named in a task is a key of `nix/tests/apps.nix` or `nix/tests/tools.nix`, `<scenario> on nix-darwin` and `<scenario> on NixOS` for a scenario of both platforms, which `sluice exec main -- moon run nix:test` prints as `nix: <case>: <what>` where it fails. Each task leaves every case of the project's test holding, so the order below matters.
- **Systems without the runner.** A case's system without the runner is `t.darwinOf [ outputs.darwinModules.default <given> ]` or `t.nixosOf [ outputs.nixosModules.default <given> ]`, as `without` in `nix/tests/apps.nix` is. A NixOS case that turns on one of Flume's, sluice's, crew's or timber's modules gives its `user`, or `services.boomdrive.user` once task 4.3 has landed (design Decision 9).
- **What no task adds or changes.**
  - No task adds a crate, a tool of the gate or a tracked file type (core.7, core.8).
  - The runner's code, the set's packages, the lock, the cache's workflow, the boot's check and the shell do not change.
  - No case reads a Markdown file (blueprints principle 16).
  - Every `.nix` file written is formatted by nixfmt and passes statix and deadnix, as `nix:format` and `nix:lint` hold it.
  - Nothing outside the paths `proposal.md`'s Touches lists is changed.
- **Comments.** A task that changes a module also says so in that module's header comment and in its options' descriptions, citing record 0023 as amended on 2026-11-18 and the design's Decision.
- **What is already written.** This change's own commit holds record 0023's amendment of 2026-11-18, record 0044's of that day, core.62, and core.18's and core.46's details. No task changes them.
