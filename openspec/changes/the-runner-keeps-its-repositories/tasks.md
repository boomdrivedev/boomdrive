# Tasks

Build the groups in order. Each group stands on the ones before it, is one session's work for an agent that has read this change (proposal, design, specs), and ends green on the moon tasks it names.

- Run each check as `devenv shell -- moon run <project>:<task>`, or through sluice as CLAUDE.md says while iterating.
- Every git call in a test runs under the scratch environment of `crates/flywheel/tests/common` (design Decision 11). No test reads the user's configuration, reaches the network, or holds a credential (core.4).
- No task adds a crate or a file type (core.7).

## 1. The configuration

- [x] 1.1 `crates/flywheel` gains a library, `src/lib.rs`, beside its binary. The root `Cargo.toml` gains `[workspace.dependencies]` for `serde` 1 (derive) and `toml` 1, which the crate takes. `src/config.rs` reads the configuration as the configuration spec has it: `repositories` required, addresses checked and compared without case, `views` absolute or `~/…` with `~/Code` as the default, `fetch_every` `<n>s|m|h` with `2m` as the default, and unknown keys refused. Every refusal names the file, the line and the key or entry, and never quotes the file's text. It also resolves the file's path and the data directory from an explicit environment (design Decisions 1 to 3; Task notes 1.1). Done when one unit test per configuration scenario other than "The default file", "The file named", "No file", "A repository added while running" and "A file broken while running" passes in `devenv shell -- moon run flywheel:test`.
- [x] 1.2 README gains "The configuration", with design Decision 2's example as a fenced `toml` block. `crates/flywheel/tests/readme.rs` parses that block with the crate's reader. `crates/flywheel/moon.yml`'s `test` task names `/README.md` among its inputs (Task notes 1.2). Done when `devenv shell -- moon run flywheel:test` passes with the README test.
- [x] 1.3 Run this group's checks. Done when `devenv shell -- moon run flywheel:format flywheel:lint flywheel:typecheck flywheel:test` passes.

## 2. Git and the scratch host

- [x] 2.1 `src/git.rs` builds every git call the crate makes. Each runs at a bare repository (`--git-dir`) or a folder (`-C`), sets `GIT_TERMINAL_PROMPT=0`, removes `GIT_ASKPASS` and `SSH_ASKPASS`, adds the caller's environment overlay, passes git no credential, and names a failure by git's last line on standard error. It also reads `git --version` against the floor of 2.48, and tells an ssh URL from any other (design Decisions 5 and 10; Task notes 2.1). Done when the unit tests of Task notes 2.1, the clones spec's "Git asks no one" and the running spec's "An old git" among them, pass in `devenv shell -- moon run flywheel:test`.
- [x] 2.2 `crates/flywheel/tests/common/mod.rs` gives each test a scratch home, git configuration and forge, as design Decision 11 has them. `tests/scratch.rs` proves that a plain `git clone https://github.com/o/r.git` under it reads the forge's commit without the network (Task notes 2.2). The crate's dev-dependencies are `tempfile` 3 and `libc` 0.2. Done when `devenv shell -- moon run flywheel:test` passes.
- [x] 2.3 `devenv.nix` pins git by `gitVersion`, asserted equal to the version of the `pkgs.git` it puts on `PATH`. `check-toolchain.sh` fails when `git --version` is not that version (design Decision 11, core.8; Task notes 2.3). Done when `devenv shell -- moon run root:toolchain root:format` passes, and `root:toolchain` says git's version.
- [x] 2.4 Run this group's checks. Done when `devenv shell -- moon run flywheel:format flywheel:lint flywheel:typecheck flywheel:test root:toolchain root:format` passes.

## 3. Clones and one pass

- [x] 3.1 `src/clone.rs` finds the runner's clones by the address each records, and makes a new one in a `.partial` folder renamed into place, as design Decisions 3 and 4 have it. A failed clone leaves nothing behind, and a folder the runner did not make is never touched (Task notes 3.1). Done when `tests/clones.rs` proves the clones spec's "A new repository is cloned", "Origin cannot be reached" and "A folder already there" in `devenv shell -- moon run flywheel:test`.
- [x] 3.2 `src/clone.rs` fetches each clone, refusing a URL the host's git rewrites to ssh. Each fetch prunes origin's deleted branches and keeps `origin/HEAD` current. The clone's HEAD follows origin's default, and its own default branch is levelled to origin's tip only as a fast-forward that no worktree holds (design Decisions 5 and 6; Task notes 3.2). Done when `tests/clones.rs` proves the clones spec's "The host rewrites https to ssh", "Origin gains a commit", "Origin deletes a branch", "One fetch fails", "Behind origin", "Held by a worktree" and "Ahead of origin", and a unit test proves `level`'s three cases, in `devenv shell -- moon run flywheel:test`.
- [x] 3.3 `src/pass.rs` makes one pass over the configured repositories, in order, each independent, with an outcome and its lines. `src/main.rs` moves to `clap` (a workspace dependency, 4, derive) with `--version`, `-V` and `run [--config <file>] [--once]`, a usage error exiting 2. `src/run.rs` holds the start's checks and the lock on `<data>/lock`, and `run --once` exits 0 or 1 (design Decisions 9 and 10; Task notes 3.3). Done when `tests/running.rs` proves the running spec's "The version", "No command", "Every repository kept", "A clone failed", "A second runner" and "A bad configuration at start", and the configuration spec's "The default file", "The file named" and "No file", in `devenv shell -- moon run flywheel:test`.
- [x] 3.4 Run this group's checks. Done when `devenv shell -- moon run flywheel:format flywheel:lint flywheel:typecheck flywheel:test` passes.

## 5. Letting go

- [ ] 5.1 `src/lacks.rs` reads the work the forge lacks in a clone and in its view: refs other than origin's and the runner's that origin's refs do not reach; worktrees other than the view, whose folders exist; the view's changes and untracked files, ignored files not counted; and a view HEAD origin's refs do not reach. Each holding is named with its words (design Decision 8; Task notes 5.1). Done when its unit tests pass in `devenv shell -- moon run flywheel:test`.
- [ ] 5.2 The pass lets go of each dropped clone. It fetches it never again. Once nothing is held, it removes the view, then the view's owner folder if empty, then the container, then the data directory's owner folder if empty. Otherwise it leaves everything and names each holding at every pass, and a folder that is not the clone's worktree is never touched (design Decision 8; Task notes 5.2). Done when `tests/dropped.rs` proves, in `devenv shell -- moon run flywheel:test`, the clones spec's "A stranger in the data directory", "Dropped while holding work", "Dropped with nothing of its own", "Emptied later", "The view's folder is not the view any more", "A branch the forge lacks", "A change in the view", "A commit in the view", "A place in the clone" and "Only ignored files"; the views spec's "The owner's last view" and "The owner's folder holds more"; and the running spec's "Left for the user".
- [ ] 5.3 A view whose recorded path the views root no longer gives is removed, as a dropped view is, before the view is made at the new path. It is left and named while it holds work, with no view made at the new path, and forgotten when its folder is gone or no longer the clone's worktree (design Decision 7; Task notes 5.3). Done when `tests/views.rs` proves the views spec's "A new root, the old view clean", "A new root, the old view holding work" and "A new root, the old folder replaced" in `devenv shell -- moon run flywheel:test`.
- [ ] 5.4 Run this group's checks. Done when `devenv shell -- moon run flywheel:format flywheel:lint flywheel:typecheck flywheel:test` passes.

## 6. The long-running runner

- [ ] 6.1 `flywheel run` without `--once` runs design Decision 10's loop: a pass at once, then one every `fetch_every` timed from the start of the pass before; the configuration read again at every pass, a pass that cannot read it doing nothing but naming it; `Notices::landed` keeping that one repository at once, and naming a repository the configuration does not name; and SIGTERM or SIGINT, through `signal-hook` 0.3 (a workspace dependency), stopping it before the next repository with exit 0. It says its start and its stop (Task notes 6.1). Done when `devenv shell -- moon run flywheel:test` proves the running spec's "Stopped while waiting" in `tests/running.rs`; its "Passes on the timer" by `next_pass`'s unit test; and, in `tests/loop.rs`, its "A failure does not stop it", the clones spec's "Told between passes" and "Told of a repository it does not keep", and the configuration spec's "A repository added while running" and "A file broken while running".
- [ ] 6.2 `tests/no_listener.rs` reads the crate's sources and `Cargo.lock` as design Decision 10 has it. `tests/running.rs` reads a pass's standard error (design Decisions 9 and 10; Task notes 6.2). Done when `devenv shell -- moon run flywheel:test` proves the running spec's "No listener in the code", "A quiet pass" and "A view moved".
- [ ] 6.3 README gains "Running on a host", and CLAUDE.md's opening says what the runner now keeps (Task notes 6.3). Done when `devenv shell -- moon run flywheel:test` passes with README's configuration block still parsing.
- [ ] 6.4 Run this group's checks. Done when `devenv shell -- moon run flywheel:format flywheel:lint flywheel:typecheck flywheel:test` passes.
