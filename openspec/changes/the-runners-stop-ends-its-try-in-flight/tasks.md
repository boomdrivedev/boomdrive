## 1. The halt

- [x] 1.1 `crates/boomdrive-bounded/src/lib.rs` gains `Halt`, a `Clone`, `Debug` and `Default` handle to one shared flag, with `halt(&self)` and `halted(&self) -> bool`, and `Stopped`, `AtLimit` or `Halted`. `output` becomes `output(command, limit, halt: &Halt)`: it reads `halt` before it spawns, and where it is set spawns nothing and returns `Ended` with `status` none, `stopped` `Some(Halted)` and both pipes empty. Otherwise it reads `halt` at each poll beside the limit, and at whichever comes first ends the group by `end_group` with `GRACE`, as at the limit today. `Ended.status` becomes `Option<ExitStatus>`, none only where no process ran, and `Ended.stopped` becomes `Option<Stopped>`, naming whichever came first. The module's documentation says a call ends at its limit or its halt, citing record 0042 as amended on 2026-11-11 (design Decisions 1 to 3). Its existing unit tests pass `&Halt::default()` and assert `Some(Stopped::AtLimit)` where they asserted `stopped`. The two callers, `git.rs`'s `bounded` and `Store::hosts` in `crates/boomdrive-crew/src/read.rs`, pass `&Halt::default()` and read the new fields, unchanged in behaviour until tasks 2.1 and 3.1. New unit tests prove the clones spec's "What a halted call started ends with it", "A halted call is given its grace" and "A call begun after its halt". `a_halted_process_is_ended_with_its_group` runs the `sh` of `a_process_that_never_ends_is_ended_with_its_group` to a limit of 60 seconds, with its halt set from a thread of the test's 300 ms in. It asserts the call returns within 5 seconds, said `Halted`, with what each pipe gave, and the background `sleep` gone within a second of the return. `a_halted_process_is_given_its_grace` runs the `sh` of `a_process_asked_to_end_says_so_in_its_grace` to a limit of 60 seconds, halted 300 ms in, and asserts `Halted` with `asked` on its standard output. `a_process_begun_after_its_halt_runs_nothing` runs `sh -c 'touch <file>'` in a temporary folder with its halt already set. It asserts `Halted`, `status` none, both pipes empty, a return within 100 ms, and no `<file>`. True when `devenv shell -- cargo test -p boomdrive-bounded` and `devenv shell -- cargo check -p boomdrive -p boomdrive-crew` pass.
- [x] 1.2 `halted(call, remote)` gives `<call> with <remote> was stopped as the runner stopped`. `a_halted_calls_words_name_its_call_and_remote` asserts `halted("git fetch", "origin")` and `halted("git ls-remote", "https://example.invalid/s.git")` (design Decision 5). ## 2. The runner's halt

- [x] 2.1 `Git` gains a private `halt: Halt`, never set from `Git::new` and `Git::default`, and `Git::halted_by(self, halt) -> Git`, as `trying_for` is. `call_remote` runs its call through `bounded` to its `try_for` and its halt. A call `Halted` fails with `Words` of `halted("git <args[0]>", remote)`, after git's last line on standard error and `; ` where git wrote one, and its standard output is not read, as a call stopped at its limit fails. `git.rs`'s module documentation says a call to a remote also ends at the runner's stop (design Decisions 4 and 5). Its unit tests prove the clones spec's "A halted fetch's words" and "A fetch begun after the stop". `a_call_to_a_remote_halted` uses a stand-in `sh`, as `a_call_to_a_remote_stopped_at_its_limit` does, that writes `fatal: half` to standard error then sleeps, with a limit of 60 seconds and its git's halt set 200 ms in. It asserts `fatal: half; git fetch with origin was stopped as the runner stopped` within 5 seconds. `a_call_to_a_remote_begun_after_its_halt` halts first and asserts `git fetch with origin was stopped as the runner stopped` alone. True when `devenv shell -- cargo test -p boomdrive --lib git::` passes.
- [x] 2.2 `Runner::start` makes the runner's halt and gives it to its git by `halted_by`. `Stopper` holds the halt. `Stopper::stop` sets the stop flag, then the halt, then sends `Event::Stop` and stops every bell. `Stopper`'s and `Runner::keep`'s documentation say a try in flight is ended at the stop (design Decision 4). `tests/common/mod.rs`'s `Scratch::silent` returns a `Silent`, with `taken(within)` and `closed(within)`, as design Decision 9 has it. `tests/running.rs` gains `stopped_with_a_fetch_in_flight`, which proves the running spec's "Stopped with a fetch in flight" for `boomdrive run`. It configures `agentplot/flume` with no clone and a silent origin, starts `boomdrive run`, and waits up to 10 seconds for the origin to take the connection. It sends SIGTERM and asserts an exit 0 within 5 seconds. It asserts the lines after the start line are `agentplot/flume: not cloned: git fetch with origin was stopped as the runner stopped` and `boomdrive: stopped`, that no folder of `agentplot/flume`'s is in the data directory, and that the origin's connection is closed within a second of the exit. True when `devenv shell -- cargo test -p boomdrive --test running -- stopped_with_a_fetch_in_flight stopped_while_waiting` passes.
- [x] 2.3 `main` calls `stop_on_signals` for `run --once` as for `run`. `Runner::once` reads the stop after its keeping pass, where it begins no part's pass and no settle once stopped, and after its parts' passes, where it begins no settle once stopped. Its documentation and `main`'s say so (design Decision 6). `tests/running.rs` gains `once_stopped_with_a_fetch_in_flight`, which proves the running spec's "Stopped with a fetch in flight" for `boomdrive run --once`. True when `devenv shell -- cargo test -p boomdrive --test running -- once_stopped_with_a_fetch_in_flight every_repository_kept a_clone_failed` passes.
