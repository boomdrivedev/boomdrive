# Tasks

A task is done once the check it names passes, run as it names it. The task groups are headings for reading: no task checks a group, and the verify stage runs the repository's whole checks once every task is done.

- Every test runs on the scratch host of `crates/boomdrive/tests/fakes`, with neutral names and paths (core.41), and no real Flume or sluice.
- No task adds a crate, a tool or a tracked file type (core.7, core.8). Nothing outside the files proposal.md's Touches lists is changed.
- Record 0002's amendment of 2026-11-14 on taking turns, and core.50's and core.55's details, already carry this change's choices (design Context). Code and tests cite them, and change neither.
- Task 1.1 leaves `sends.rs`'s `a_pass_past_due_sends_each_launchs_answer_before_its_next_launch` and `a_send_that_fails_leaves_the_passs_answers_to_its_end` failing, since they ask a pass past due for more than one launch. Tasks 2.1 and 2.3 rewrite them to the spec's scenarios.

## 1. Once due, a pass makes no launch after its first

- [x] 1.1 In `crates/boomdrive/src/carry.rs`, the work counts each `flume launch` it runs, whatever Flume answers, and none for a launch found by its mark. Once `Carrier::due` says the next pass is due and the count is above zero, an offer that would be launched, every check of `Work::offer` passed and its clone standing, is answered `held` with the words `waits for the next control pass, which is due`, its room counted at its turn, said in one line where the answer changed, and no `flume launch` is run (design Decisions 1 and 2). The module's, `Round`'s, `Carrier::due`'s and the work's doc comments say so. Done when `devenv shell -- cargo test -p boomdrive --test turns -- a_pass_due_from_its_start_makes_one_launch a_pass_that_falls_due_among_its_launches_makes_none_more a_launch_held_for_its_turn_counts_against_its_streams_room` passes, the new file `crates/boomdrive/tests/turns.rs` proving the work-into-flume spec's "A pass due from its start makes one launch", "A pass that falls due among its launches makes none more" and "A launch held for its turn counts against its stream's room".
- [x] 1.2 Between the rounds, a launch that waited on its clone's keep is held the same way once the pass is due and has run a launch, without waiting on the keep (design Decision 2). Done when `devenv shell -- cargo test -p boomdrive --test offers -- a_launch_that_waited_on_its_clones_keep_is_held_without_waiting_on_it` passes, proving the spec's "A launch that waited on its clone's keep is held without waiting on it" with `offers.rs`'s keeper.
- [x] 1.3 A launch held for its turn has its acts answered as a held launch's, and the pass's first act runs after its first launch, so launches and acts take turns (design Decisions 1 and 2). Done when `devenv shell -- cargo test -p boomdrive --test turns -- a_drop_of_a_launch_held_for_its_turn an_act_waits_behind_one_launch_once_the_pass_is_due a_pass_that_falls_due_among_its_launches_runs_its_first_act_next` passes, proving the spec's "A drop of a launch held for its turn", "An act waits behind one launch once the pass is due" and "A pass that falls due among its launches runs its first act next".

## 2. Once due, a send goes before each command

- [ ] 2.1 Once the next pass is due, the work sends its share before each tool's command it runs for a want, a `flume launch` in turn or once its clone's keep is done, Flume's status of a place or its command for an act, and sluice's preview or release, and once it has answered its last want, wherever an answer changed the share since its last send, reaching the pass's control plane where it runs the command; it no longer sends after each want. The share is still saved after every want (design Decision 3). Done when `devenv shell -- cargo test -p boomdrive --test sends -- a_pass_past_due_sends_a_launchs_answer_before_its_act_runs a_pass_past_due_sends_each_launchs_answer_before_its_next_launch a_pass_not_yet_due_sends_once_at_its_end an_acts_answer_goes_up_before_the_next_act_runs` passes, the first test new, the second rewritten to its scenario's new words, proving the requirement "A pass past due sends each answer as it makes it" and its four scenarios.
- [ ] 2.2 After a send before a command, the want about to run is taken anew, and nothing runs for it where it or its launch was let go or refused; no want let go or refused at a send of the pass, and no act on a launch let go or refused, is taken more that pass (design Decision 4). Done when `devenv shell -- cargo test -p boomdrive --test sends -- a_want_refused_at_a_send_of_the_pass_is_taken_no_more an_act_whose_launch_is_let_go_at_the_send_before_it_runs_nothing` passes, the first test rewritten to its scenario's new words and the second new, proving the spec's "A want let go at a send of the pass is taken no more" and "An act whose launch is let go at the send before it runs nothing".
- [ ] 2.3 A send that fails before a command leaves the pass's answers to its end, as before (design Decision 3; core.22). Done when `devenv shell -- cargo test -p boomdrive --test sends -- a_send_that_fails_leaves_the_passs_answers_to_its_end` passes, the test rewritten to the spec's "A send that fails leaves the pass's answers to its end" in its new words.
