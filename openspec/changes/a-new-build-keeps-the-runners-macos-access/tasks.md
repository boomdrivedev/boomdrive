## 1. The signing step

- [x] 1.1 `nix/modules/activate.sh` gains `sign <keychain> <folder> <program>`, in its header comment and its usage lines beside `link`, `keep` and `plugins`. The step makes `<folder>` with `mkdir -m 0755` where it is not there. It reads the folder's owner and mode from `ls -ldn`. Where the owner is not `id -u`, or the mode gives write to the group or to others, it makes no identity, signs nothing and writes nothing in the folder. It then says `boomdrive: <folder> is writable by a user other than <user>: signed nothing` and exits 1. Throughout the step, a line of what it made goes to standard output and a refusal to standard error, as `link`'s do. `nix/tests/activate.sh` gains the stubs of design Decision 7, and `id` answers `-u` with the case's own uid. It also gains the case "A folder another user can write", which runs the step twice: once with the folder `chmod g+w`, once `chmod o+w`. Each run asserts the line, exit 1, no call of `security`, `codesign` or `openssl`, and an empty folder (design Decision 3). True when `sluice exec main -- moon run nix:test` passes.
- [ ] 1.2 The step finds the identity by the distinct SHA-1s on the lines naming `"Boomdrive runner"` in `security find-identity -p codesigning <keychain>`. With none, it makes one as design Decision 2 has it. It writes the OpenSSL configuration and runs `openssl req -x509 -newkey rsa:2048 -nodes -days 7300` in a folder made by `mktemp -d` under `umask 077`, which a trap removes. It runs `security import key.pem -k <keychain> -x -T /usr/bin/codesign`, then `security import cert.pem -k <keychain>`, and says `boomdrive: made the code-signing identity Boomdrive runner, <SHA-1>, in <keychain>`. A refused import removes the folder, says `boomdrive: could not make the code-signing identity in <keychain>: <its words on one line>`, signs nothing and exits 1. Two or more identities sign nothing and say `boomdrive: <keychain> holds <n> identities named Boomdrive runner, <SHA-1>…: signed nothing; remove all but one`, then exit 1. The cases "No identity yet", "No key in a file", "An identity that cannot be made" and "Two identities of the name" prove the service-modules spec's scenarios of those names. "No key in a file" finds no file reading `key` or `cert` in the case's folder or in the folder `openssl` wrote in (design Decision 2). True when `sluice exec main -- moon run nix:test` passes.
- [ ] 1.3 The step makes a copy where `<folder>/boomdrive` is not there, `<folder>/boomdrive.source` does not hold `<program>`, or `codesign --verify -R '=certificate leaf = H"<SHA-1>"' <folder>/boomdrive` fails. Otherwise it says nothing and exits 0. To make one, it copies `<program>` to `<folder>/boomdrive.new` with mode 0755. It runs `codesign --force --sign <SHA-1> --keychain <keychain> --identifier boomdrive --timestamp=none` on it, and moves it to `boomdrive` by `mv -f`. It writes `<program>` to `boomdrive.source.new` and moves that to `boomdrive.source`. It then says `boomdrive: signed <folder>/boomdrive, made from <program>, with Boomdrive runner, <SHA-1>`. A failed `cp` or `codesign` removes `boomdrive.new`, leaves `boomdrive` and `boomdrive.source` as they were, says `boomdrive: could not sign <program> into <folder>: <its words on one line>` and exits 1. The cases "A new build", "The same build", "A copy signed with another identity" and "A signing refused" prove the spec's scenarios of those names. "The same build" asserts no signing call of `codesign` and both files' bytes unchanged. "A signing refused" asserts the folder holds only `boomdrive` and `boomdrive.source`, as they were (design Decision 4). True when `sluice exec main -- moon run nix:test` passes.
