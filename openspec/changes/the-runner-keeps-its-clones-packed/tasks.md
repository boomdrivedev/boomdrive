# Tasks

A task is done once the check it names passes, run as it names it. The task groups are headings for reading: no task checks a group, and the verify stage runs the repository's whole checks once every task is done.

- Every test runs on the scratch host of `crates/boomdrive/tests/common`, with neutral names and paths (core.41), its git under the scratch's own configuration, and no real Flume or sluice.
- The clones spec's new scenarios are proved in a new test file of the crate's, `crates/boomdrive/tests/packs.rs`, whose module comment names the clones spec, record 0051 and core.14. Its helpers write a clone's loose objects by one `git hash-object -w --stdin-paths`, its packs by one `git pack-objects` each, set a loose object's file time back by days, and read a clone's counts by `git count-objects -v`. A test that needs its own `between` or `stop` calls `boomdrive::pass::pass` in-process, as `Scratch::pass` does.
- No task adds a crate, a tool, a tracked file type or a key of the configuration (core.7, core.8, core.17). Nothing outside the files proposal.md's Impact lists is changed.
- Record 0051 and core.14 as amended, with core.13's details, already carry this change's choices (design Context). Code and tests cite them, and change neither.

## 1. Git's own collection is off in every clone

- [ ] 1.1 In `crates/boomdrive/src/clone.rs`, `make_in` sets `gc.auto` to `0` and `maintenance.auto` to `false` with the clone's other keys, before its first fetch, and its doc comment and the module's say so (design Decision 1). Done when `devenv shell -- cargo test -p boomdrive --test packs -- a_new_clones_collection_is_off an_agents_commit_starts_no_collection` passes, the new file `crates/boomdrive/tests/packs.rs` proving the clones spec's "A new clone's collection is off" and "An agent's commit starts no collection".
- [ ] 1.2 A new function of `clone.rs` reads `gc.auto` by `git config --local --type=int --get` and `maintenance.auto` by `--type=bool`, and writes each by `git config --local` only where it is missing or reads otherwise. `keep` in `crates/boomdrive/src/pass.rs` calls it for a found clone after its drive is recorded and before its fetch; where it fails, the pass says `<address>: git's own collection not turned off: <git's words>`, its outcome is failed, and the keep goes on to the fetch, the HEAD and the view (design Decision 1). Done when `devenv shell -- cargo test -p boomdrive --test packs -- a_clone_made_before_is_turned_off_at_its_next_pass a_clone_whose_config_cannot_be_written` passes, proving the spec's "A clone made before is turned off at its next pass" and "A clone whose config cannot be written", the second with a `config.lock` made beside the clone's config.

## 2. A keeping pass packs a clone once what arrived passes git's bound

- [ ] 2.1 In `clone.rs`, a clone's counts, its loose objects and its packs, are read from `git count-objects -v`'s `count` and `packs`, and one pure function says whether its occasion has come: more than 6,700 loose objects or more than 50 packs, the two bounds constants beside it, each doc comment naming git's `gc.auto` and `gc.autoPackLimit` (design Decision 2). Done when `devenv shell -- cargo test -p boomdrive --lib -- clone::tests::an_occasion_comes_past_either_bound` passes, a new unit test of `clone.rs` holding the function at and past each bound.
- [ ] 2.2 In `clone.rs`, a clone is packed by `git repack -q -d -l --cruft --cruft-expiration=2.weeks.ago`, then `git prune --expire=2.weeks.ago`, then `git commit-graph write --reachable`, each by `Git::run`, the first that fails ending the pack with git's words (design Decisions 3 and 4). In `pass.rs`, once the pass has kept and let go of every repository, kept the workspaces and cleared partial clones, it goes through the repositories the configuration keeps, in its order, each with a clone among the pass's clones, holding no lock: it reads the clone's counts, packs it where its occasion has come, and says `<address>: packed <n> loose objects and <m> packs`, with `1 loose object` and `1 pack` for one, and nothing of a clone below both bounds. `pass`'s doc comment says so (design Decision 5). Done when `devenv shell -- cargo test -p boomdrive --test packs -- nothing_is_packed_at_the_bound loose_objects_past_the_bound packs_past_the_bound a_dropped_repository_is_not_packed` passes, proving the spec's "Nothing is packed at the bound", "Loose objects past the bound", "Packs past the bound" and "A dropped repository is not packed".
- [ ] 2.3 The packing round reads `stop` before each clone and packs none once it is set, and calls `between` after each clone it packs, finding the clones again where `between` kept a landing (design Decision 5). Done when `devenv shell -- cargo test -p boomdrive --test packs -- a_landing_told_while_the_pass_packs a_stop_while_the_pass_packs` passes, proving the spec's "A landing told while the pass packs", whose test's `between` keeps `agentplot/timber` by `boomdrive::pass::keep_one` once `agentplot/flume` is said packed, and "A stop while the pass packs", whose test's `between` sets the pass's `stop` then.

## 3. What a pack drops and leaves

- [ ] 3.1 A pack drops only the objects nothing of the clone reaches that were written more than two weeks before (design Decision 3). Done when `devenv shell -- cargo test -p boomdrive --test packs -- an_old_object_nothing_reaches_is_dropped what_a_place_and_sluice_hold_is_kept` passes, proving the spec's "An old object nothing reaches is dropped" and "What a place and sluice hold is kept", each clone brought past the bound by 51 packs.
- [ ] 3.2 A pack packs no ref, expires no ref's log and prunes no worktree (design Decision 4). Done when `devenv shell -- cargo test -p boomdrive --test packs -- refs_logs_and_worktrees_are_left_as_they_were` passes, proving the spec's "Refs, logs and worktrees are left as they were", its ref's log entry written a year before by `git update-ref --create-reflog` under `GIT_COMMITTER_DATE`.

## 4. A pack that fails is named

- [ ] 4.1 Where counting a clone's objects or a step of its pack fails, the pass says `<address>: not packed: <git's words>`, runs no later step, fails, and still packs every other clone (design Decision 6). Done when `devenv shell -- cargo test -p boomdrive --test packs -- one_pack_fails` passes, proving the spec's "One pack fails", the clone's `objects/pack` made unwritable and then writable again by the test.

## 5. The README

- [ ] 5.1 README's list of what a keeping pass does gains a bullet: git's own collection is off in every clone, `gc.auto` at `0` and `maintenance.auto` at `false`, so no fetch or commit there starts one; and once every repository is kept, the pass packs each kept clone holding more than 6,700 loose objects or more than 50 packs, dropping only what nothing of the clone reaches past two weeks, touching no ref, log or worktree, and saying `<owner>/<name>: packed <n> loose objects and <m> packs`. No formatter owns Markdown (`treefmt.nix`), so done when `grep -F "git's own collection is off" README.md` and `grep -F 'more than 6,700 loose objects or more than 50 packs' README.md` each print a line.

## 6. The specs archive under openspec's strict check

- [ ] 6.1 Each requirement the change's delta spec adds states its behaviour in under openspec's 500 characters, so archiving it passes `root:specs`. Done when, with the change archived by `devenv shell -- openspec archive the-runner-keeps-its-clones-packed --yes`, `devenv shell -- openspec validate --specs --strict --no-interactive` passes; the archive is then undone, uncommitted, for the verify stage to make.
