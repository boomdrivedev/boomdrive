# Tasks

Build the groups in order. Each group stands on the ones before it, is one session's work for an agent that has read this change (proposal, design, specs) and its Task notes, and ends green on the moon tasks it names. A task is true once the moon task it names passes, run as it names it.

- Run each check as `devenv shell -- moon run <project>:<task>`, or through sluice while iterating, as CLAUDE.md says.
- `the-runner-carries-crews-work-into-flume` and `the-runner-keeps-its-protocol-as-one-json-schema-per-version` are built and on `main` (design, *What this change rests on*, 1). Where a type or a schema file differs from what a task needs, take it as it stands and name it in your summary.
- Tests reach nothing beyond the loopback address, never touch a keychain, credential or configuration of the user's, and run no real Flume, sluice or `systemd-creds` (design Decision 14).
- Every key, field, type, module and message a task adds names what it holds (core.12). Tests and examples use neutral names, such as partitions `home` and `work`, repositories `example/app` and `example/service`, and `https://control.example`, and hold no real control plane's address (core.41).
- No token, key or credential is in a tracked file, a fixture or a commit message (core.4). A test's token and key are made by the test, or fixed bytes named as a test's own.
- Every dependency a task adds is pinned by `Cargo.lock`, and none serves HTTP or WebSockets (core.3, core.8).
