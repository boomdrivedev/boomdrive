# Tasks

Build the groups in order. Each group stands on the ones before it, is one session's work for an agent that has read this change (proposal, design, specs) and its Task notes, and ends green on the moon tasks it names. A task is true once the moon task it names passes, run as it names it.

- Run each check as `devenv shell -- moon run <project>:<task>`, or through sluice while iterating, as CLAUDE.md says.
- `the-runner-carries-crews-work-into-flume` is built and on `main` (design, *What this change rests on*, 1). Where a type of `flywheel-control`'s differs from design Decision 6's list when a task needs it, carry the type's form into the schema and name it in your summary.
- Tests reach no network. Every validator is built from `FILES` alone, and `jsonschema` is built with no default features (design Decisions 2 and 13).
- Every file, field and type a task adds names what it holds (core.12), as design Decisions 2, 5 and 13 name them. Examples use neutral names, and copy no path, host or name from a fixture (core.41).
- Nothing outside `crates/flywheel-hosted`, the rules test and the files design Decision 15 and Task notes 1.1 name is changed. `flywheel-control`, crew's implementation, `planes.rs` and the runner's report file stay as they are (design Decision 6).
